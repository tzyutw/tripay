## 阻斷點 ①：記帳表單沒有「匯率」欄位，幣別是行程層級

`src/components/ExpenseFormSheet.tsx` 的金額區只有兩個輸入框：

- **外幣金額**（`foreign_amount`）＋「稍後再填」toggle
- **台幣金額**（`twd_amount`）＋「稍後再填」toggle
- 匯率是**唯讀衍生顯示**：`匯率 ≈ 台幣 ÷ 外幣`（第 356–360 行），且兩欄都填才顯示

送出時（第 174、183–187 行）：

```js
exchange_rate: null,
// 兩欄都有值時才回填
if (foreignAmount && twdAmount && fa > 0) expData.exchange_rate = ta / fa;
```

**幣別沒有 per-expense 欄位**，只有 `trips.currency`（行程層級單一幣別）。

→ prompt 的幣別規則「現金消費：照當地貨幣記 `foreign_amount`，**並設定現金匯率**（用 Excel 記載的當日匯率）」
   在現行 UI **無法照字面執行**——沒有可以「設定匯率」的地方。
   prompt 也明確要求：「找不到就停下回報，**不要用別的欄位硬湊**」。

## 阻斷點 ②：結算引擎只吃台幣，外幣完全不進結算

`supabase/functions/_shared/settlement-engine.ts` 與 `calculate-settlement/index.ts`：

- 查詢只取 `twd_amount`（`select("id, payer_member_id, twd_amount, expense_type, is_sponsor")`）
- `foreign_amount` **從未參與** payout / cost / net_balance 任何計算
- 且有硬性防線：
  ```js
  if (!Number.isFinite(exp.twd_amount) || (exp.twd_amount < 0 && !sponsorOk))
      return json({ error: "invalid_amount", expense_id: exp.id }, 422);
  ```

**後果**：若照 prompt 字面「現金只記外幣、不填台幣」，該筆 `twd_amount = null`
→ 整趟結算直接回 **422**（除非把它標成 `twd_pending`，但那會讓它被排除在結算外，基準 B 必然對不上）。

## 阻斷點 ③：基準 B 的比對幣別，與 Tripay 的輸出幣別不一致

prompt 說「以比對幣別計；台幣比台幣、日幣比日幣」。但實際上：

| 行程 | Excel「給X」欠款欄的幣別 | Tripay 結算輸出幣別 | 能否直接 ±1 比對 |
|------|----------------------|------------------|----------------|
| 2023 福岡 | （無欠款欄） | 台幣 | 基準 B 不適用 |
| 2024 東京 | **日幣** | 台幣 | ❌ 幣別不同 |
| 2025 北海道 | **日幣** | 台幣 | ❌ 幣別不同 |
| 2026 濟州島 | **台幣** | 台幣 | ✅ 可直接比 |

東京與北海道的每人淨額是日幣（如 Ning +¥92,946），Tripay 只會給台幣淨額。
換算會受「每日匯率不同 ＋ 每筆四捨五入」影響，**±1 元的容許度在跨幣換算下不可能穩定達成**。

---

## 建議的解法（需 Rozi 拍板才動工）

**針對 ①②：兩個金額欄都填，讓衍生匯率等於 Excel 當日匯率**

- 外幣金額 ← Excel 的當地貨幣金額（¥／₩）
- 台幣金額 ← 外幣金額 × Excel 記載的**當日匯率**（福岡 J 欄、東京/北海道/濟州島的日期列）

這樣：UI 顯示的「匯率 ≈」就**恰好是 Excel 的當日匯率**，等同於「設定了現金匯率」；
同時 `twd_amount` 有值，結算不會 422，基準 B 可驗。
這不是「用別的欄位硬湊」——用的就是原本那兩個金額欄，只是把匯率用兩邊金額表達。
**但它偏離 prompt 字面（prompt 說刷卡「不為刷卡設定單一匯率」），所以需要 Rozi 同意。**

**針對 ③：基準 B 的比對基準二選一**

- (a) **在原幣比對**：驗證腳本從 Tripay 讀 `foreign_amount` 自行推算每人日幣淨額，與 Excel 日幣淨額比 ±1。
      優點：真的「日幣比日幣」。缺點：驗的是我算的，不是 Tripay 結算頁顯示的數字。
- (b) **在台幣比對**：把 Excel 的日幣淨額用該趟匯率換成台幣當基準，容許度放寬到 ±(人數) 元。
      優點：驗的是 Tripay 真正輸出的結算。缺點：容許度必須放寬，不是 ±1。
- **建議 (b)，容許度放寬**，因為驗收目的是「Tripay 結算對不對」，不是「我的腳本算不算得出日幣」。
