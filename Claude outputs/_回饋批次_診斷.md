## 批次 4（2026-09-06 手機實測，Rozi 陸續丟）

### R5-1 🔴 匯率欄位每打一個字，鍵盤就收起來一次（「0.19」要輸入四次）
- **根因確診**：`src/components/shared/CashRate.tsx:16`
  ```tsx
  export default function CashRate({...}) {
    const Row = ({ side }) => { ... <input className="rateinput" .../> ... };
    return <div className="ratebox"><Row side={first}/><Row side={second}/></div>;
  }
  ```
  `Row` 是**在元件內部定義的函式元件**，每次 `CashRate` 重新 render 都是一個
  **全新的函式參考**。React 視為不同的元件型別 → **卸載舊 DOM、掛載新的** →
  `<input>` 被銷毀重建 → 焦點消失 → iOS 鍵盤收起。
  打一個字 → onChange → setState → re-render → input 重建 → 失焦。**每個字都要重點一次。**
- **原型早就寫過這條鐵律**（`Tripay_原型.html:2219`）：
  > 只更新衍生內容——**不重建任何 input**（#13 的教訓、規格 §5.5 明訂）
  屬 A 類（實作沒接上原型的規則），不是原型缺口。
- **修法**：把 `Row` 移到 `CashRate` 外面（模組層級），或直接把兩列 JSX 內聯展開。
  **不要**用 `useCallback` 包——那不能解決元件型別每次都變的問題。
- **驗收**：真實瀏覽器連續輸入 `0`→`.`→`1`→`9` 四鍵，
  期間 `document.activeElement` 必須恆等於同一個 `#rate-for` 節點（用 `isSameNode` 比對，
  不是比 id——重建後 id 一樣但節點不同）。反向驗證：把 `Row` 移回去，該條必須紅。
- **全站同型掃描**（Cowork 已跑）：只有這一處。
  `SettlementPage.tsx:246` 的 `const Nav = (...)` 是 JSX 值不是元件，不受影響。

### R5-3 🔴 回歸：「新增一種支付方式」輸入框從 39px 塌成 26px
- **Cowork 的指令造成的。** 實作-J 要求用 `:where()` 降權重（為了修破框），
  把 `input[type=text]{…padding:9px 10px…}` 整條降到特異度 (0,0,0)，
  結果被 Tailwind preflight 的 `input{padding:0}`（0,0,1）蓋掉。
- 量到（`?screen=s02b` 390×844）：該框 **26.0px / paddingTop 0px**，應為 ≈39px。
- 全站掃描：**只有這一個受害**（其餘輸入框都有自己的 class 或 Tailwind 高度）。
  - `.rateinput` 38px（自帶 padding:4px 0）、S-02「去哪？」46px（`h-[46px]`）、
    S-04 三個 28px（`.fieldrow>input`／`.amtline input`，設計上就是無框內嵌）
- 修法：拆兩條——外觀維持 (0,1,1) 壓過 preflight，只有 `width` 用 `:where()` 降到 0。
- **教訓**：`:where()` 降權重前要先確認 Tailwind preflight 沒有 reset 同一個屬性。
  降到 0 之後連 preflight 都蓋得過。只降真的會跟 utility 打架的那幾個屬性。
