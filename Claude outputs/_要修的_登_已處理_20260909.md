## 登-1：登入失敗的時候，畫面要說話

### 現況（Cowork 2026-09-08 實際量到的，不是讀碼推論）

- `auth.users` 整個資料庫只有一個帳號。Rozi 的家人用別的 Google 帳號登入，
  **帳號從來沒有被建立過**。
- Supabase 端沒有擋：`/auth/v1/settings` 回 `disable_signup: false`、`google: true`。
- `handle_new_user` trigger 實跑過（`begin … rollback`），正常建 profile。
- `get_shared_trip()` 以 `anon` 身分實跑過，132 筆讀得到——分享連結沒壞。
- 根因在 Google Cloud Console 那一側（Rozi 自己處理），**但這一項要修的是另一件事**：

**Rozi 的家人選完 Google 帳號之後，畫面直接跳回登入頁，一個字都沒有。**

原因有兩處：

1. `src/pages/LoginPage.tsx` 的 `handleGoogleLogin` 只有
   `await supabase.auth.signInWithOAuth({...})`，**回傳的 `error` 沒有接**。
2. OAuth 失敗時 Supabase 會把錯誤放在導回網址的 **hash**
   （`https://tzyutw.github.io/tripay/#error=access_denied&error_description=...`）。
   目前沒有任何一段程式讀它；`AuthLayout` 只看到 session 是 `null`，
   就 `<Navigate to="/login" replace />`，錯誤參數在轉址中被丟掉。

### 要做

**(a)** `LoginPage` 掛載時，從**網址的 hash 與 query 兩處**找 `error` / `error_description`
（Supabase 放 hash，少數情況放 query，兩個都要看），有值就顯示訊息區塊。

⚠️ 錯誤參數是掛在 `/`（BASE_URL）上、不是掛在 `/login` 上的。`AuthLayout` 轉去 `/login` 時
**hash 會被 react-router 保留還是丟掉，你要自己實測**——如果丟掉，就得在更上層
（`App.tsx` 或 `AuthLayout` 轉址前）把它撈出來帶過去。**不要假設，跑一次看**。

**(b)** 訊息顯示在「用 Google 繼續」按鈕**上方**，同一個 240px 欄（`.s00col`）之內。
文案（Copywriter 定稿，逐字照抄，不要自己改寫）：

- 標題：`登不進去`
- 內文：`Google 沒有讓這個帳號登入 Tripay。換一個 Google 帳號試試看。`
- 小字：`還是不行的話，把下面這行傳給分享行程給你的人：`
- 原文行：`Google 的回覆：{error_description}`
  （`error_description` 要 URL decode，`+` 要還原成空白。沒有 `error_description`
  就退回顯示 `error` 本身；兩個都沒有就不顯示原文行。）

**不要**照 error code 分支寫十種文案——一種就好。

**(c)** 顯示完之後把網址上的錯誤參數清掉（`history.replaceState`），
不然重新整理又跳出來。

**(d)** `signInWithOAuth` 回傳的 `error` 也要接，接到就走同一個訊息區塊
（原文行顯示 `error.message`）。

### 停止條件（機器判得出來，Cowork 會自己跑一次）

- **登-1-1** 開 `#/login` 並在網址帶 `#error=access_denied&error_description=Test+reason`，
  **畫面上**（渲染結果，不是原始碼字串）出現「登不進去」
- **登-1-2** 同一畫面出現「Test reason」（**空白已還原**，不是 `Test+reason`）
- **登-1-3** 訊息出現後 2 秒內，`location.hash` 與 `location.search` 都不再含 `error`
- **登-1-4** 沒有錯誤參數時，登入頁**不得**出現「登不進去」（反向斷言）
- **登-1-5** 只有 `#error=access_denied`、沒有 `error_description` 時，
  畫面出現「登不進去」且出現 `access_denied`
- **登-1-6** 顯示訊息的狀態下，375／390／430 三個寬度都不橫向捲動（C4）
- **登-1-7** 顯示訊息的狀態下，「用 Google 繼續」鈕的有效可點區仍 `h ≥ 44`（C6）
