## ① S-02／S-02b 的日期欄位沒有用已經移植好的 `.datefield`（跑版、沒間距、高度不對）

**現象（iPhone Safari 實測）**：建立／編輯行程的 sheet **會左右跑版**；
「出發」「回程」兩欄看起來黏在一起、中間沒有間距；出發欄的日期文字被切掉。

**根因（一處）**：`src/components/TripFormSheet.tsx:483–508` 的日期列是**自己寫的 Tailwind**：
```
<div className="mb-5 flex gap-3">
  <div className="flex-1 min-w-0">
    <input type="date" lang="en" className="w-full h-[46px] px-[14px] … border-[1.5px] border-[#E4DFD9] …" />
```
沒有關掉系統外觀、沒有日曆圖示、高度 46px、gap 12px。
iOS Safari 的原生 `input[type=date]` 在**沒有** `-webkit-appearance:none` 時，
寬度由作業系統決定、且會用 zh-TW 長格式（`2026年9月24日`），比一半的欄寬還寬 → 整列撐出 sheet。

**已經有現成的正確做法，只是沒被用到**：`src/index.css:226–230` 已經把原型的 `.datefield`
整組移植過來了（`-webkit-appearance:none`、`flex:1;min-width:0;padding-right:32px`、
`height:40px`、`::-webkit-date-and-time-value{height:20px;line-height:20px}`、
右側絕對定位的日曆 icon）。**這一輪就是把畫面接上它。**

**要做的**：把日期列改成與原型 `Tripay_原型.html:1195–1200` 同一個結構——
```
<div style="display:flex;gap:9px">            ← gap 9px，不是 12px
  <div style="flex:1;min-width:0">
    <label>出發</label>
    <span class="datefield"><input type="date" …/>{calendar icon 16}</span>
  </div>
  <div style="flex:1;min-width:0">
    <label>回程</label>
    <span class="datefield"><input type="date" … min={startDate}/>{calendar icon 16}</span>
    <p class="hint">不填就是當天來回</p>
  </div>
</div>
```
高度交給 `.datefield`（40px），**不要再寫 `h-[46px]`**；邊框／圓角沿用 `.datefield` 那一套，
不要用 `border-[1.5px] border-[#E4DFD9]` 這種寫死值。`lang="en"` 拿掉（外觀已關，格式由我們控制）。
S-02b（編輯行程）同一列一起改，兩處共用同一段 JSX，不要寫兩份。

**原型註解已經寫明為什麼**（`Tripay_原型.html:196–208`，#34-4 第三次修同一個地方）：
高度必須明確給，因為 iOS 關掉外觀後**空值裡面什麼都不畫**，那一行會塌成 0，
造成「回程比出發矮一截」。這正是 Rozi 這次又看到的東西。

### 停止條件

1. `grep -c "h-\[46px\]" src/components/TripFormSheet.tsx` **等於 0**。
2. 日期列的兩個欄位都在 `.datefield` 裡，且各自的父層有 `flex-1 min-w-0`；
   兩欄之間的 gap **等於 9px**。
3. **版面斷言要量「sheet 自己」，不是只量 document**：
   在 320／375／414 開啟建立行程 sheet，斷言
   **sheet 容器的 `scrollWidth <= clientWidth`**（現有的 `實作_版面回歸測試.cjs`
   只量 `document.documentElement`，所以這次沒抓到——**這一條要補進去**）。
   反向驗證：把 `min-w-0` 拿掉 → 該條要紅。
4. 兩欄高度相等（容差 1px），空值與有值都要量。

## ② 新增行程不可以預填上一趟的成員（這是 2026-09-04 已經移除的功能）

**現象**：按「新增行程」，成員清單直接帶進上一趟的四個人，並顯示
「已帶入上一趟的成員，可以改」。Rozi 的情境是**開一趟全新的**，不該有這些。

**根因（一處）**：`src/pages/TripListPage.tsx:179`
```
prefill={!editTripId && latestTripId ? { tripId: latestTripId, mode: 'members' } : undefined}
```

**這是被復活的舊功能**：`專案狀態.md:422` 白紙黑字——
`~~G-09 預填成員：新增行程帶入上一趟成員（依出發日取最新），附可改提示~~ ← 2026-09-04 移除`。
原型 `Tripay_原型.html` 裡也**完全找不到**「已帶入上一趟的成員」這句話。

**要做的**：
1. `TripListPage.tsx` 新增行程時 **不要傳 `prefill`**（`mode:'members'` 這條路整個不要）。
   `latestTripId` 若因此沒有其他用途，一併移除，不要留沒人用的查詢。
2. `TripFormSheet.tsx:516` 那句 `'已帶入上一趟的成員，可以改'` 文案刪掉。
   **`mode:'full'`（複製行程）那條路要保留**——那是另一個功能，
   它的文案「已帶入原本那趟的成員與幣別，可以改」不要動。
3. 新增行程的成員區起始狀態，照原型 S-02 的樣子（空白列 ＋「新增成員」）。

### 停止條件

1. `grep -c "已帶入上一趟" src/` **等於 0**。
2. `grep -n "mode: 'members'" src/` **沒有結果**。
3. 新測試：render 建立行程 sheet（**沒有 prefill**）→ 成員列的數量等於原型 S-02 的起始數量，
   且畫面上**找不到**「已帶入」三個字。反向驗證：把 prefill 傳回去 → 該條要紅。
4. 另一條測試：`mode:'full'`（複製行程）**仍然**帶入成員與幣別，文案是
   「已帶入原本那趟的成員與幣別，可以改」——確認沒有把複製功能一起砍掉。
