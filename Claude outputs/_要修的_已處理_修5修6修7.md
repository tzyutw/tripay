## 修-6　下拉重新整理「太硬」——換成 iOS 的橡皮筋曲線

Rozi 原話：「有點太硬，可以參考 iOS 的設計嗎？」

**根因**：`usePullToRefresh.ts` 用的是**固定阻尼** `setPull(dy * 0.5)`，
所以手指從第一毫米開始就只有一半的位移——一開始就重。
iOS 的 rubber-banding 不是固定比例，是**遞減**的：一開始接近 1:1，拉越遠越黏。

**改成蘋果的橡皮筋公式**（`UIScrollView` 的那一條，c = 0.55）：

```ts
const RUBBER_C = 0.55;
const RUBBER_DIM = 300;               // 參考尺度，不是上限
const rubber = (dy: number) =>
  (1 - 1 / ((dy * RUBBER_C / RUBBER_DIM) + 1)) * RUBBER_DIM / RUBBER_C;
```

換算對照（`THRESHOLD` 維持 60）：

| 手指拉 | 舊（×0.5） | 新（橡皮筋） |
|---|---|---|
| 20px | 10 | 19 |
| 60px | 30 | 54 |
| **70px** | 35 | **60 ← 剛好到門檻** |
| 120px | 60（舊的門檻在這） | 98 |
| 200px | 90（撞上限） | 146 |

也就是：**現在要拉 120px 才觸發，改完 70px 就到**，而且前 20px 幾乎是 1:1 跟手。
`MAX_PULL` 從 90 放寬到 **120**（公式本身會自然趨緩，不需要硬切）。

**回彈也要改**：現在放開是 `setPull(0)` 瞬間歸零，沒有過渡，這是「硬」的另一半。
加一段回彈動畫：`transition: transform 280ms cubic-bezier(0.23, 1, 0.32, 1)`
（只在放開的那一刻套用，拖曳過程中不能有 transition，不然會跟手指脫節）。

⚠️ 不要引入任何動畫套件。⚠️ 不要動「只在捲動容器已在最頂端才觸發」那段判斷。

**停止條件**
1. `usePullToRefresh.ts` 裡 `dy * 0.5` 這種固定比例**出現 0 次**
2. 拉 **70px** 放開 → 會觸發重新整理；拉 **40px** 放開 → 不觸發（反向）
3. 放開時有 transition，拖曳過程中沒有（量 computed style）
4. 行程列表與行程詳情兩處都適用

## 修-7　重新整理轉太久要講話

Rozi 原話：「重新整理的狀態可以設定幾秒沒反應就跳出提示狀態嗎？一直 loading 看起來很像更有問題」。

**做法**：下拉觸發的重新整理，**10 秒**沒回應就：
1. 停止轉圈（`refreshing` 回 false）
2. 跳 toast **`MSG_SAVE_OFFLINE`（「現在連不上網路」）**——**不要新增字串**，
   用既有的那一句。使用者的下一步一樣（等一下再拉一次），沒必要多一種說法。
3. 畫面上原本的資料**留著不動**（跟離線時看得到舊資料一致）

⚠️ 10 秒到了要**中止**那個請求（`AbortController`），不要放著它背景跑完再默默更新——
「畫面說連不上、三秒後資料自己變了」比一直轉更難懂。

**停止條件**
1. `?fail=hang` 下拉觸發重新整理 → **12 秒內**轉圈停止、且畫面出現「現在連不上網路」
2. 正常情況下拉重新整理 → 不得出現那句話（反向）
3. `messages.ts` **沒有新增任何字串**
